# 中文汇报、报告例子库

这些是用户提供的表达偏好示例，用来理解修改方向，不是禁词表或机械替换规则。省略部分不代表可以删除原稿中的实质信息。示例中的产品判断不作为外部事实来源。

## 记号

代码块保留用户简记：`\` 表示同类例子并列；`////` 标注文体；`#` 表示开头；`……` 表示省略；箭头右侧的空双引号 `“”` 表示删除匹配内容；括号表示注释；`!!!!` 标记重点。记号仅帮助阅读，不作为正则表达式执行。其他位置的引号属于原句表达。

## ZH-REPORT-001：删除开场套话

来源：用户初始语料。适用：未提供实质限定的报告开头。

```text
////汇报、报告
#“先明确一点”……\#“先说一点”…… ----> “”（删去开场套话，保留后文）
```

理解：直接进入观点；若后面的“一点”承载关键条件，条件必须保留。

## ZH-REPORT-002：展开判断过程

来源：用户初始语料。

```text
“……我判断时先去掉这个功能……” ----> “……我判断这个功能……的时候会先试着把这个功能去掉……”
```

理解：补足判断对象和操作顺序，让语义随着过程展开；“试着”应符合原文的试验性语气，不能擅自改变已执行动作的事实。

## ZH-REPORT-003：将入口表述改为具体行为

来源：用户初始语料。

```text
“……、……、……、……、……、（功能）是用户日常沟通和关系维护的主入口。”
----> “用户日常沟通、关系维护大都通过……、……、……、……（功能）完成”
```

理解：从用户做什么出发组织句子。省略号及列举数量仅为示意，实际改写保留必要功能项；“大都”等范围词须有原稿依据。

## ZH-REPORT-004：展开压缩称呼（重点）

来源：用户初始语料。

```text
“微信支持单聊、群聊、文字、语音、……（功能）等，……”
----> !!!!“微信支持一对一聊天、群聊…………”
（用户认为“单聊”这样的缩写不如“一对一聊天”自然。）
```

理解：采用面向一般读者的完整说法；不把用户对这个词的评价扩展成所有行业缩写的事实判定。

## ZH-REPORT-005：回扣核心功能（重点）

来源：用户初始语料；以下保留原始目标句及其笔误。

```text
!!!!“微信支付显著提升体验和粘性，也有很强商业价值，但即使没有支付，微信的聊天核心仍可成立；支付是可替代、可外部完成的增强能力，不是微信存在的根本原因。”
----> “微信支付显著体验用户体验和用户粘性……但……微信“聊天”依旧是其核心功能，支付是锦上添花的增强能力……”
```

理解：回扣“聊天”这一讨论对象，减少重复的否定论证，以贴切的成语表达增强作用。目标句“显著体验用户体验”按明显笔误理解，实际输出使用“显著提升用户体验”；引号嵌套按成稿规范处理。用户省略的商业价值、替代性等信息若是当前论证所需，应保留，不能照着省略号删掉。

## ZH-REPORT-006：删去重复的自我流程预告

来源：用户先前提供的开头示例。

```text
#“我……，我……，我……，然后我……” ----> “”
```

理解：适用于开头只重复预告自己将如何回答的内容；真实经历、必要流程或有意的文学排比不在此例删除范围。
